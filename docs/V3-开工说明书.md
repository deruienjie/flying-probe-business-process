1. **以 `data.js` 为唯一数据源**，不新建一套平行数据；全景所需的新内容也写进 `data.js`。
2. **不改现有阶段名称、顺序、业务内容**（除非用户明确同意，见第 6 节待定项）。
3. **不虚构**：
   - 真实项目成果 / 个人研究 / 示意流程，三者必须在页面上区分并标注
   - KPI 没有真实数据就只写名称，不写改善比例、不写金额

4. **先本地截图确认，再推线上**。不许未经确认直接 push / 覆盖 GitHub Pages。

### 数据模型

`MODEL[]` 每个阶段：

```js
{ id:"P1", name:"市场与销售", color:"#2563eb", goal:"…",
  crossCutting?: true,            // P9 财务用
  matrix?: {...},                 // P9 独有的模块×环节矩阵
  segments?: [{ id:"A", name:"…", goal:"…", steps:[…] }],   // P1/P9 有段
  steps?: […]                     // P2–P8 只有环节，没有段
}
```

每个微环节：

```js
{ id:"A1", name:"…", who:[], inputs:[], actions:[], outputs:[], systems:[],
  judge:"判定/卡点", ai:"可自动|可辅助|只能人做", aiNote:"…",
  kpis:[], risks:[], module?:"金蝶模块名" }
```

### 路由（hash）

| hash | 含义 | 状态对象 |
|---|---|---|
| `#phase:P4` | 阶段页 | `{kind:"phase",id}` |
| `#seg:A` | 段视图（表格+抽屉） | `{kind:"segment",id}` |
| `#A3` | 段视图 + 抽屉定位该条 | `{kind:"focus",id}` |
| `#step:A3` | 微环节详情页 | `{kind:"step",id}` |
| `?pick=G1#seg:G` | 手机端直接弹底部抽屉 | — |

**V3 新增路由建议**：`#overview`（业务全景）、`#sysmap`（系统映射）、`#about`（说明页），对应新的 state kind，`resolve()` 与 `go()` 里各加一个分支即可，不要动上面四个。

### 关键函数（都在 app.js）

- `render()`：按 `state.kind` 分发到 `viewPhase / viewSegment / viewStep`
- `bind()`：绑 `[data-go]`（走 `resolve`）、`[data-focus]`、`[data-pick]`、`[data-detail]`
- `go(s)`：设置 state → render → 写 hash → 滚动复位
- `stats()` / `strip()` / `insights()` / `advice()`：统计与建议块，可复用
- 移动端：`isMobile()`、`syncSheet()`、`toggleSide()`

## 3. V3 要做的（砍过后的范围）

### 3.1 顶部导航

四个入口：**业务全景 / 流程拆解 / 系统映射 / 项目总结**

- 先上「业务全景」与「流程拆解」（已有能力）
- 「系统映射」可从数据派生，做真实矩阵
- 「项目总结」只做"作品说明 + 真实性声明"，不编经历
- 手机端：导航收进 ☰ 菜单或底部 tab，**不能挤爆顶栏**

### 3.2 业务全景页（本次重点）

1. **端到端主线**：P1–P8 横向卡片，卡片间箭头
   - 每张卡：阶段名 / 核心内容（`PHASE_IO.core`）/ 输入→输出（`PHASE_IO.in/out`）/ 段数与环节数 / 涉及系统
   - 点卡片 → `#phase:Pn`
2. **P9 财务横贯**：单独一条泳道在主线下方，用虚线连到各阶段，**不能排成"最后一步"**
3. **关键单据流**：取 `BILL_FLOW`（15 个节点，已按真实 outputs 校对过）
   - 每个节点可点 → 对应微环节
   - 明确标注"主链"，不要暗示所有单据都串在一条线上
4. **核心流程图**：取 `CORE_FLOW` 做「商机 → 交付」
   - 9 个主节点 + 4 个分支 + 1 个回退（报价被拒回方案调整）
   - **必须标注「示意流程，不代表某公司实际审批路径」**
   - 手机端退化成列表，不要硬塞 SVG

### 3.3 层级联动

全景 → 阶段 → 段 → 微环节，全部复用现有路由。
从详情返回全景时要保留浏览上下文（记住之前点的是哪个阶段）。

### 3.4 视觉

- 企业级、克制：白底卡片 + 细边 + 悬停上浮 2px，不加背景图 / 粒子 / 玻璃拟态
