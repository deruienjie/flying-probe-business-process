## 一、财务阶段的定位：横贯，不是最后一步

财务数据不是交付之后才产生的：

- 应收起于**订单**（预收款）
- 应付起于**入库**（暂估）
- 存货起于**仓储**（出入库）
- 成本起于**领料/报工**

所以在网页上：

- 作为**第 9 个阶段**追加在最后（结算视角）
- 顶部 Ribbon 用**虚线框**标记「横贯阶段」，提示它不是一个时间点
- 其它 8 个阶段结构不动

## 二、拆成 7 个段、36 个微环节

| 段 | 名称 | 微环节 | 核心内容 |
|---|---|---|---|
| G | 应收与开票 | 6 | 预收 → 发货开票 → 应收单 → 核销 → 账龄催收（含质保金） |
| H | 应付与采购结算 | 5 | 入库暂估 → **三单匹配** → 应付入账 → 付款审批 → 外协结算 |
| I | 存货核算 | 5 | 入库成本 → 出库计价 → 月末结账 → 盘点差异 → 在制结转 |
| J | 成本核算 | 7 | 成本对象 → 材料/人工/制造费用 → 外协专项 → 完工与在制 → 成本还原 |
| K | 总账与报表 | 5 | 单据转凭证 → 审核过账 → 期末关账 → 三大报表 → 管理报表 |
| L | 税务与发票 | 4 | 进项认证 → 销项合规 → 增值税申报 → 税负分析 |
| M | 资金与预算 | 4 | 资金计划 → 收付款排程 → 银行对账 → 预算控制 |

设计上刻意保留的几个"坑"（面试可讲）：

- **暂估不冲回** → 重复计成本
- **三单不一致直接付款** → 单价差异永远查不出来
- **计价方法选错** → 整个成本失真
- **成本对象混乱** → 项目之间串成本
- **在制长期挂账** → 毛利虚高
- **科目映射错误** → 报表全错

## 七、补充：移动端适配（当天下午）

面试官很可能用手机点开链接，原来 `≤860px` 直接把抽屉和侧栏 `display:none` 了，等于手机上不能用。

按 **A 方案（最小可用）** 做了：

| 断点 | 处理 |
|---|---|
| `≤820px` | 左侧树 → 侧滑抽屉（☰）+ 遮罩；表格每行 → 卡片（`data-label` 竖排）；抽屉 → 底部弹层（带把手、✕、遮罩关闭）；分隔条隐藏；顶栏精简 |
| `821–1180px` | 左右栏收窄，保持三栏 |
| `>1180px` | 桌面版不变 |

踩的坑：基础样式里有一条 `@media (max-width:860px){ .drawer,.aside{display:none} }`，优先级比后写的移动端规则高，导致弹层有 `.open` 类但 `display:none`，截图里只看到遮罩变暗、看不到面板。加 `display:block` 覆盖后解决。

验证：用 iframe 包一层 390×844 的"手机画框"来截图（Chrome headless 在 macOS 上窗口最小 500px，直接设 390 会被夹住）。

新增深链：`?pick=G1#seg:G` 打开就直接弹出 G1 的详情。
